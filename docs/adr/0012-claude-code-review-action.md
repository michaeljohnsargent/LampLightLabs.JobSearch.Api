# ADR 0012: claude-code-review GitHub Action

## claude-code-review GitHub Action reviews every PR against this repo's own conventions

`.github/workflows/claude-code-review.yml` runs `anthropics/claude-code-action` on every PR open/sync and posts a review comment. The prompt explicitly points it at this repo's `CLAUDE.md` — versioning structure, the auth schemes, the Strategy Pattern used for `ICsvReaderService`/`IJobStore`, the characterization-testing rule for `StatusCategorizerService`, and the async job/DI-scope pattern in `JobsController` — so review feedback is scoped to deviations from patterns already established here, not generic style nits. It's read-only (`Read,Grep,Glob`, plus `Bash(gh pr diff:*)`/`Bash(gh pr view:*)`) and comment-only: `mcp__github_comment__update_claude_comment`/`mcp__github_inline_comment__create_inline_comment` let it post the review, nothing lets it push commits. Runs with `track_progress: true`, pinned to `claude-sonnet-5`, `--max-turns 40`. Requires an `ANTHROPIC_API_KEY` repository secret, added once in GitHub settings.

## Why the review action needed four rounds of fixes (2026-07-30 to 2026-07-31)

Round 1: the first four runs had no model pin (defaulting to the priciest available tier) and no cheap way to see the PR diff — `--allowedTools` only granted `Read`/`Grep`/`Glob`, so the agent had no `git`/`gh` access and fell back to exhaustively reading files while repeatedly attempting disallowed tools. 16–22 permission denials and 54–68 turns per run, $2–3 each, one run failing outright. Fixed by pinning the model and granting `Bash(gh pr diff:*)`/`Bash(gh pr view:*)`, mirroring `anthropics/claude-code-action`'s own `examples/pr-review-comprehensive.yml`. Round 2: cost dropped ~80% but the run still failed — turned out **every run, including the "successful" ones, had posted zero comments and zero reviews since this workflow was created**. Root-caused from the action's own source (`src/mcp/install-mcp-server.ts`): this workflow runs in "agent mode" (a custom prompt, not a `@claude` mention), and agent mode only loads the comment-posting MCP server if `--allowedTools` explicitly requests it — which it never did. The agent analyzed every PR correctly and then had no way to deliver the result. `track_progress: true` forces "tag mode," which always loads the comment server and creates the tracking comment `update_claude_comment` needs to exist before it can update it; `mcp__github_inline_comment__create_inline_comment` needs its own explicit grant regardless of mode. Round 3: comment delivery was confirmed working, but two runs still hit `--max-turns`. Rather than guess again, spent one diagnostic run with `show_full_output: true` (reverted after) to see the actual tool-call transcript: ~9 of ~31 turns were spent on denied Bash calls the agent kept retrying — `npm test` in four-plus forms, one `git fetch origin main`, one `find` across the filesystem. It wasn't missing a needed tool; it was trying to *execute* things (run the suite, search the filesystem) it should only *read*. Both diagnostic runs actually completed a full, genuinely useful review and posted it before erroring on turn count, so the failures were largely cosmetic — but still wasted turns and cost. Fixed with an explicit prompt instruction on what's available and to evaluate tests by reading them, not running them, instead of granting broader (and riskier) Bash access. Round 4: denials dropped from 9 to 4 per run, but verification runs still hit `--max-turns 30` despite completing a full, useful review both times — the run status showed "failure" for what was functionally a success. Bumped to `--max-turns 40` for headroom so the status matches reality; the real cost fix was round 3, this just clears the remaining margin.

## Two Claude Code hooks scope what the agent can touch and when a turn is "done"

`.claude/settings.json` wires up:
- A `PreToolUse` hook (`block-secrets.js`) on `Read`/`Edit`/`Write` that blocks any `appsettings.*.json` override (e.g. `appsettings.Development.json`) or `.env`/`.env.*` file by filename, regardless of directory. The base `appsettings.json` is exempted — it only ever holds placeholder values (see **AI Integration**, **Semantic Kernel Integration** in the README) — so the agent can still read the shape of the config without a path to real secrets, which live only in user secrets or an environment-specific override file.
- A `Stop` hook (`run-tests.js`) that runs both suites — `dotnet test` and `npm test` in `client/` — before a turn is considered finished, so a broken build or a broken test can't silently pass as "done." The backend run passes `--filter "FullyQualifiedName!~Counter_WithoutLock_ProducesUnpredictableResults"` to exclude just that one method: it's the intentionally-broken half of the Threading Concepts exercise, and without the filter the hook would report a failed turn on every single stop regardless of what changed, since that test is designed to never pass.
